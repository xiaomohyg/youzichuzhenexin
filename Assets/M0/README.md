# M0 第一人称战斗沙盒

依据工程外的 `M0开发规格.md` 制作。打开 `Assets/M0/Scenes/M0Sandbox.unity`，点击 Play。原来的 `Assets/Scenes/SampleScene.unity` 与两个原型脚本保留。

## 默认操作

| 操作 | 默认按键 |
| --- | --- |
| 移动 / 转向 | WASD / 鼠标 |
| 奔跑 / 跳跃 | 左 Shift / 空格 |
| 闪避 | Q；同时按方向键决定方向，无方向时向前 |
| 近战普通连击 / 远程射击 | 鼠标左键 |
| 近战格挡 / 完美格挡 | 按住鼠标右键；0.1 秒前摇后有 0.13 秒完美窗口 |
| 近战重击 | E |
| 近战 / 远程切换 | Tab |
| 重置沙盒 | R |
| 下蹲 / 第一第三人称切换 | 按住左 Ctrl / V |
| 物品栏 | I；I 或 Esc 关闭 |
| 快捷栏选择 | 滚轮上下切换（循环），数字 1–5 直接选择 |
| 暂停 / 设置 | Esc，固定保留，不参与改键 |

底部提示实时读取当前绑定。Esc → 按键设置 → 点击按键 → 按新键；支持键盘键和鼠标按钮，Esc 取消，重复绑定交换两个动作。保存到 PlayerPrefs，重开游戏仍生效。继续游戏的点击不会同时触发攻击。菜单暂停战斗与角色操作。可恢复默认绑定。

## 玩法与调参

- 橙色头部是弱点，射击头部立即击杀；瞄准头部的近战有适当放宽的判定。
- 敌人巡逻、感知追击、红光蓄力、出拳、后摇、硬直与死亡。新方块护甲模型有肩肘动作、护甲分层、头盔与橙色头部弱点；原六刚体尸体、复用池与弱点功能保留。
- 怪物仅在出拳动作 20%–80% 的有效窗口内，用可见拳套大小的盒体沿实际位置和旋转轨迹细分扫掠，与玩家胶囊接触才结算，每次出拳最多结算一次。前摇、收招和普通身体碰撞不造成伤害。方向在出拳时锁定，墙体阻挡拳套轨迹和接触路径，硬直/死亡取消攻击。
- 近战三段分别为斜斩、反向横扫、上挑；E 为蓄力下劈。动作分为前摇、快速挥击、收势；允许结束前 0.2 秒缓存下一击。Q 闪避和鼠标右键格挡可取消攻击。
- 手臂有肩、肘、腕表现，武器为自制阶梯轮廓的挤出像素钢剑，采用点采样纹理；不是商业游戏模型。`M0PlayerRig` 只负责表现，`M0Player` 负责时序与命中。
- 闪避 3.4 米 / 0.52 秒，踏步—爆发—减速三阶段，手臂收拢、身体下压，视角不翻滚；无敌 0.2 秒、冷却 0.85 秒。普通格挡减伤 90%，有抬剑与受击回弹；完美格挡让敌人硬直 1.1 秒。格挡仅保护前方。
- 实际躲过攻击或完美格挡可获得 1.2 秒反击窗口；下一次命中的近战 +25% 伤害。成功闪避还触发 URP 全场景灰度与 0.25 倍时流，持续约 0.72 秒（真实时间），末段平滑恢复。成功条件为无敌期间拳套接触当前胶囊，或挥击轨迹穿过本次闪避离开的胶囊；空闪不会触发。
- 格挡受击增加短暂向后冲量，使用原 CharacterController 处理墙体碰撞；完美格挡后坐较小。双手、剑和第三人称身体有阻尼回弹与后仰。菜单/物品栏冻结成功闪避特效计时，关闭后继续；重置清除慢动作，退出恢复时钟与物理步长。
- 下蹲平滑调整眼高、碰撞体与速度；低矮顶棚阻止起身。V 切换肩后第三人称，带相机墙体避让；第三人称射击从角色眼部发射，避免隔着掩体利用相机射击。
- 命中停顿只冻敌人；弱点击杀停顿更长。轻微震动、伤害数字、火花、准星命中标记、射线轨迹与程序合成占位音效。
- 尸体使用六个刚体及五个关节。落地并稳定后冻结，保留实体碰撞，可垫脚。26 个复用槽，最多保留 20 具尸体，超限回收最旧。自动补充敌人可在设置关闭。
- FOV 默认 94，菜单可调到 90–100；震动可关闭，轻微头晃默认关闭。灵敏度、视野、震动、头晃、音量保存到 PlayerPrefs。
- `Player / FPV controller` 的 `M0Player` 暴露移动、伤害、闪避、格挡、后坐力、停顿与击退参数；敌人组件暴露血量、速度、感知、前摇等参数，Play 中可热调。
- 游戏使用自制方块模型与占位音效。五分钟主观爽感和舒适度仍需玩家实际试玩评价。

## 物品栏基础

20 格背包，前 5 格为快捷栏，初始为钢剑、手枪和三个空格。滚轮向下选择下一格，向上选择上一格，两端循环；空格收起武器并禁止攻击/格挡。Tab 在快捷栏里的非空武器之间切换。

I 打开背包并暂停单机训练；左键依次点两个格子交换物品，右键快捷栏格子装备。装备移入背包时自动收起。物品栏打开时滚轮用于界面滚动，不切换装备。全部新增键盘操作可改键，旧十二项绑定文件会迁移并保留。

`M0Inventory` 是独立状态类，提供 `TryAdd`、`Swap`、`Select`、`Snapshot`、`Revision` 与 `Changed`，后续拾取可以调用添加接口。当前只包含两件训练武器，不包含掉落、合成、消耗品、物品存档或真实网络同步。

## 联机模块预留（M2）

`Scripts/Networking/M0Network.cs` 包含 `IM0Transport`、`PlayerCommand`、`ActorSnapshot`、`HitMessage`、`LocalTransport`；`M0NetworkSession.cs` 提供可挂载的会话组件。

当前是可运行的单机权威 + 本地队列回环，50Hz FixedUpdate 收集命令，每三次 tick 发送角色快照。暂停界面中的“联机模块预留”显示收到的命令、快照、命中计数。它没有建立真实多人连接。

命令预留下蹲和快捷栏索引，玩家快照带下蹲、选中格与物品栏修订号。完整物品交换/拾取请求仍需未来服务端鉴权；修订号本身不构成完整背包同步。

纯 C# `CombatRules` 负责伤害、弱点、无敌和格挡规则；`ICombatTarget` 是受击入口；`CombatEvents` 解耦特效、音效、相机与网络消息。命中消息携带目标 ID。

后续 NGO 接入点：

1. 实现 `IM0Transport` 的 NGO 适配器，初始化时替换 `LocalTransport`，设置房间、Host/Client 和身份管理。
2. 在服务端消费玩家命令；当前 `M0Player` 为本地驱动，模板还未接管其运动。验证 tick、玩家身份、冷却、距离与命中，复用 `CombatRules`。
3. 客户端接收快照并对远端角色插值；表现层订阅服务器确认的命中事件。不要接受客户端直接提交的伤害结果。
4. 为尸体选定同步策略：服务端同步死亡与初始冲量，客户端表现 ragdoll；可垫脚的碰撞必须与服务端保持一致。补充预测、回滚 / 延迟补偿、断线重连及双客户端测试。

未安装 NGO / Relay / Lobby，不依赖外部网络服务。此处只完成接口与本地验证骨架。

## 运行验证

Play 中运行菜单 `M0/Validate Running Sandbox`。测试通过真实 Input System 输入验证移动、闪避、改键、绑定保存与冲突交换；另外验证身体射击、头部弱点、物理尸体冻结、格挡、尸体上限、重置与本地消息传递。

结果写入工程根目录 `Validation/M0-validation.txt`。测试结束恢复之前的按键配置，重置沙盒并停在暂停界面。截图位于工程根目录 `Screenshots`。

`M0EnemyRig` 负责怪物动作；`M0Enemy` 负责动作窗口、接触扫掠和伤害；`M0DodgeEffect` 负责灰度、时钟恢复与暂停协调。未来联机时应由服务端确认闪避成功，再在客户端触发灰度表现；当前全局时流仅用于单机训练，不能直接当作多人同步策略。

Play 中 `M0/Validate Contact Combat Upgrade` 验证真实 AI 出拳接触、侧移打空、墙体阻挡、硬直中断、空闪、成功闪避、灰度慢动作的暂停/物品栏恢复以及格挡后坐碰撞，报告为 `Validation/M0-contact-validation.txt`，挥击轨迹为 `Validation/M0-punch-trajectory.txt`。`M0EnemyActionCapture.Run()` / `Run(true)` 用实际 AI 动作分别录制怪物全身和格挡后坐帧，输出到 `Screenshots/EnemyUpgrade`。
